armux 0.4.1 lets Claude Code read and drive armux's built-in browser, moves paste to `Ctrl+V`, and adds quicker keys for tabs, workspaces and panes.

## Install

1. Download `armux-0.4.1-win-arm64.zip` below and extract it anywhere, for example `%LOCALAPPDATA%\Programs\armux`. To upgrade, close armux and replace the old files.
2. Run `armux.exe`.

You need Windows 11 on ARM64 with the Windows App Runtime 1.8 and the WebView2 Runtime (both are usually already installed).

## New

- **Browser tools for Claude Code.** `armux mcp` is an MCP server that gives Claude Code 14 `browser_*` tools for armux's browser tabs: list and open tabs, navigate, back, forward and reload, a page snapshot with element refs, page text, click, fill, type, press keys, scroll, run JavaScript, take a screenshot and read the console.
  - It is off until you turn on Settings › Browser › Let agents control the browser.
  - Turning the setting on adds armux to Claude Code's MCP servers (`~/.claude.json`), with no command to run; turning it off removes it. Restart Claude Code sessions that were already open.
  - Clicks and keys go into the page through WebView2's DevTools protocol, never through Windows input. Password values are hidden in snapshots.
  - It uses tabs that already have a page and never opens extra WebViews, so the two-live-tabs memory cap still holds.
- **`Ctrl+V` pastes** in a terminal. In text boxes it stays their own paste. `Ctrl+Shift+V` still works.
- **`Ctrl+Tab`** goes through every tab in the workspace, pane by pane. **`Ctrl+Shift+Tab`** goes to the next workspace.
- **`Ctrl+arrows`** move to the pane in that direction. With no pane there, the key goes to the program, so word jumps in the shell keep working. `Ctrl+Alt+arrows` still work.

## Fixed

- Shortcuts work wherever the keyboard is: in browser tabs, in the explorer and in text boxes. Before, most only worked with a terminal focused. Clipboard, arrow and undo keys still edit a focused text box or web page. On the Settings page only `Esc` and `Ctrl+,` act, and both close it.
- After a split or closing a pane, the pane that moved could stop redrawing: the shell kept running, but the pane stayed blank or stale until you switched workspaces and back.

## Changed

- The window can't be made so small that the title bar runs under the minimize, maximize and close buttons. The limit follows the sidebar, zoom and display scale, and a long workspace name is cut short with "…".
- `armux open` prints the new tab's id and leaves the keyboard in the terminal.
- After the window is resized, armux refits and redraws every terminal and tells programs that track focus (Claude Code) to redraw.
- The control pipe answers several clients at once, so a slow page doesn't hold up `armux notify`.
- Previous Tab no longer has a default shortcut, and Next Workspace's default moved to `Ctrl+Shift+Tab` (`Ctrl+PageDown` still works). Rebind either in Settings › Keyboard.
